# 笔记类型 UI 开发规范

> 实现现状对照见 `docs/architecture/01-笔记类型架构.md`。

## 一、整体架构

```
NoteType (enum)
    │
    ├── XxxData (data class)     ← 类型化数据模型（lib/domain/note_data）
    ├── XxxCard (widget)         ← 卡片预览（lib/features/notes_list/widgets/cards）
    ├── XxxEditor (widget)       ← 编辑器面板（lib/features/notes/widgets/editors）
    └── XxxPreview (widget)      ← 完整预览（lib/features/notes/views/previews，可复用 XxxCard）
```

### 三阶数据流

```
用户操作 → Editor → onChanged(data) → NoteEditorPage 持有 data → 保存时 toJson() → DB
DB → Note(content: json) → dispatch → XxxData.fromJson(json) → Card / Preview
```

**所有 JSON 解析在 dispatch 处做一次**，之后各层只操作类型化 data。

### 2.1 每类一个 Data 类

定义于 `lib/domain/note_data/`，每种类型一个不可变 data class：

```

├── drawing_data.dart
├── bank_card_data.dart
├── contact_data.dart
├── account_data.dart
├── voice_data.dart
└── calendar_data.dart
```

### 2.2 契约

```dart
class MoodData {
  final String mood;
  final String noteField;  // 用 noteField 避免与 Note.content 混淆

  const MoodData({required this.mood, this.noteField = ''});

  factory MoodData.fromJson(String json);  // 永不抛异常
  String toJson();
}
```

**规则：**
- `fromJson` **绝不抛异常**，解析失败返回 `defaultValue()`
- 附加文字字段统一命名 `noteField` / `remark`，不叫 `note`
- 如果类型支持 Markdown 导出，在 data class 上加 `String toMarkdown()`
- 如果类型需支持全文搜索，加 `String get searchableText`

### 2.3 JSON 工具

```dart
// lib/core/utils/json_helpers.dart
Map<String, dynamic>? safeDecode(String? json);
```

不允许再复制 `_parseJson`。

## 三、编辑器层

### 3.1 统一接口

```dart
abstract class NoteEditor<T extends NoteData> extends StatefulWidget {
  final T? initialData;
  final ValueChanged<T> onChanged;

  const NoteEditor({super.key, this.initialData, required this.onChanged});
}
```

### 3.2 规范

| 方面 | 要求 |
|------|-------|
| 初始化 | 在 `initState` 中调用 `_emit()` 确保父组件收到初始值 |
| `_emit()` | 始终调用 `onChanged`，永不条件跳过 |
| dispose | 释放所有 `TextEditingController` |
| 参数 | `initialData` + `onChanged` 必选；额外可选参数用命名参数 |
| 数据流 | 单向：编辑 → `_emit()` → `onChanged(data)` |
| 编辑器尺寸 | 控制在 100-180 行，超过则拆子组件 |

### 3.3 text / textV2 例外

- **text**：包装 `RichTextEditorController`（外部包）为 `TextEditor`。布局保留 `Column + Expanded`（富文本需要独立空间）。
- **textV2**：`TextV2Editor` 使用 `QuillController`（flutter_quill），工具栏可由用户在设置中配置（`providers/editor_toolbar_config.dart`）。
- 其他类型统一用 `SingleChildScrollView`。

## 四、卡片层

### 4.1 统一接口

```dart
abstract class NoteCard<T extends NoteData> extends StatelessWidget {
  final T data;
  final VoidCallback? onTap;

  const NoteCard({super.key, required this.data, this.onTap});
}
```

需要 State 时用 `StatefulWidget`。

### 4.2 规范

| 方面 | 要求 |
|------|-------|
| 输入 | `data` 为 `T` 类型，不传 raw `Note` |
| 大小 | 40-80 行 |
| 颜色 | 全部使用 `Theme.of(context).colorScheme` |
| 位置 | `lib/features/notes_list/widgets/cards/`（timeline 与 dashboard 共用） |

## 五、预览层

### 5.1 文件组织

```
lib/features/notes/views/previews/
├── text_preview.dart
├── text_v2_preview.dart
├── mood_preview.dart
├── link_preview.dart
└── ... (每个类型一个)
```

`note_preview_page.dart` 只做 dispatch，不再内联渲染。

### 5.2 卡片 vs 预览

| 场景 | 使用 |
|------|------|
| Timeline / Dashboard 列表 | `XxxCard`（紧凑，可点击进预览） |
| Preview page 完整查看 | `XxxPreview`（组合 card + 操作栏） |
| 导出 Markdown | `XxxData.toMarkdown()` |

```dart
class LocationPreview extends StatelessWidget {
  const LocationPreview({super.key, required this.data, this.onEdit, this.onDelete});

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        LocationCard(data: data),             // 复用卡片
        const SizedBox(height: 16),
        ActionBar(onEdit: onEdit, onDelete: onDelete),  // 复用操作栏
      ],
    );
  }
}
```
