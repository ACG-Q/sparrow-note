# 表格块交互重构方案（参考 Typora）

日期：2026-10-26
状态：设计稿，待确认后实施

---

## 一、为什么要重构

### 现状的三个问题

1. **原生浮钮会跟着内容滚走**
   BlockNote 的行手柄、列手柄、加行/加列 `+` 都在 `.tableWrapper` 内部，属于"表格内容"的一部分。
   实测（10 列 × 15 行，1400px 窗口）：横向滚到底后，行手柄从 `x=632` 跑到 `x=90`，已经在容器外，点不到。

2. **和左侧 `⋮⋮` 菜单重复**
   `⋮⋮` 菜单里已经有「颜色」「删除」（还有表头开关），再叠一条功能相近的浮动工具条，等于两套入口。

3. **工具条与表格脱节**
   表格比块窄时，工具条贴在块的右上角，离表格本体两百多像素，看着像浮在空白里。

### 目标

- 屏蔽 BlockNote 自带的表格浮钮
- 在**表头正上方**放一条常驻工具条（Typora 的做法）
- 表格相关动作同时出现在**左侧 `⋮⋮` 菜单**里，两处命令一致
- 宽表、长表、触屏都能用

## 二、Typora 是怎么做的（官方文档事实）

来源：[Table Editing · Typora Support](https://support.typoraio.cn/Table-Editing/)（2017-02-28 发布，2025-01-17 更新）

### 工具条的位置

> "Put the cursor inside a table and a **table tooltip will show above the table header**."

光标进入表格后，**表头正上方**出现一条工具条，宽度与表格一致。

从左到右（依据官方截图）：

| 位置 | 元素 | 行为 |
|---|---|---|
| 最左 | 3×3 网格图标 | 点开「尺寸选择器」：一个网格图 + `6 × 10` 两个输入框 + OK |
| 左二~四 | 三档对齐图标 | 给**当前列**设置左/中/右对齐 |
| 中右 | 三个行列图标 | 行列的插入/删除 |
| 最右 | 垃圾桶 | 删除整个表格 |

### 各操作的具体入口

| 操作 | Typora 的入口 |
|---|---|
| 新建表格 | 写 `\|First Header \| Second Header\|`，或菜单栏插入 |
| 加行 | 光标在行内按 `Ctrl/Cmd+Enter` 在下方插入；`Tab` 也能加；或右键菜单 |
| 删行 | `Shift+Alt+Ctrl/Cmd+L`、`Shift+Ctrl/Cmd+Backspace`，或右键菜单 |
| 加/删列 | **右键菜单**（工具条上没有直接按钮） |
| 调整表格尺寸 | 工具条最左的网格图标 → 网格或输入 `行 × 列` → OK |
| 列对齐 | 工具条上的三档对齐图标 |
| 移动行列 | 拖拽行/列左（上）边框 |
| 表头 | Markdown 第一行即表头；`⋮⋮` 菜单里有「切换表头行/列」 |

### 值得抄的三点

1. 工具条**长在表格上**（表头上方），不是浮在页面某个角落
2. 尺寸用一个**网格 + 数字输入**解决，而不是"加一行/加一列"点很多次
3. 命令**同时**存在于工具条和菜单/快捷键里，习惯哪个用哪个

### 不抄的

- 右键菜单（我们的编辑器右键是浏览器菜单，另做一套成本高，先不做）
- Touch Bar（macOS 专属）

## 三、目标形态

```
┌──────────────────────────────────────────────┐  ← 表格顶部的工具条（常驻，不随内容滚动）
│ ▦ 3×3   ≡左 ≡中 ≡右   ＋行 ＋列   ⋯          │
├─────────┬────────┬──────────┬───────────────┤
│ 项目    │ 数量   │ 备注     │               │  ← 表头行
├─────────┼────────┼──────────┼───────────────┤
│ 块类型  │ 24     │ 全量覆盖 │               │
└─────────┴────────┴──────────┴───────────────┘
```

- 工具条左边缘与表格左边缘对齐；表格横向滚动时，工具条**不动**（它不在滚动容器里）
- `⋮⋮` 菜单（左侧）新增一个「表格」分组，包含同样的命令：

```
⋮⋮ → [颜色 >]
     [表格 >]   插入行 / 插入列 / 删除行 / 删除列 / 合并 / 拆分 / 切换表头
     [删除]
```

## 四、交互规格

### 工具条按钮

| 按钮 | 行为 | 备注 |
|---|---|---|
| `▦ 3×4` | 打开尺寸面板：网格拖选 + 行列数输入 + 确定 | 缩容会删掉末尾的行列，需二次确认 |
| `≡左 ≡中 ≡右` | 给光标所在**列**设置对齐 | 写 `textAlignment`，与 Markdown `:---:` 语义一致 |
| `＋行` | 在当前行**下方**插入 | 与 Typora 的 `Ctrl+Enter` 一致 |
| `＋列` | 在当前列**右侧**插入 | |
| `⋯` | 菜单：合并选中、拆分单元格、删除本行、删除本列、**删除表格** | |

### 显示/隐藏

| 场景 | 行为 |
|---|---|
| 指针在表格内 | 显示 |
| 光标（选区）在表格内 | 显示（触屏靠这个） |
| 指针移到工具条上 | **保持显示**（不能因为离开表格就收起，否则点不到） |
| 选区离开表格 | 隐藏 |
| 表格滚出可视区 | 隐藏 |

### 定位

- 以**表格本体**（`<table>`）的矩形定位，不是整个块——避免块比表格宽时飘在空白里
- 左边缘 = `max(表格左缘, 可见区左缘)`，避免横向滚到尽头时工具条跑出屏幕
- 顶部 = `表格顶 - 工具条高度`；上方空间不足时落在表头内部上沿
- `position: fixed` + 滚动/缩放时重算（保持上一版的实现，已验证不会随内容滚动）

### 触屏

- 工具条在块顶部**常显**（不依赖 hover）
- 按钮最小点击区 44×44（现状 10px 字号太小，需放大到 14px / 高度 32）
- 尺寸面板的网格支持点击（不是 hover）

## 五、技术方案

### 1. 屏蔽原生浮钮（CSS）

```css
[data-content-type="table"] .table-widgets-container,
[data-content-type="table"] .bn-table-handle,
[data-content-type="table"] .bn-extend-button,
[data-content-type="table"] .bn-table-cell-handle {
  display: none !important;
}
```

已在上一版加过，实测 `widgets: 0`，但 `.bn-table-handle` 仍有 2 个可见——需要确认是哪些元素（可能是 resize handle 与 cell handle 复用了 class），逐一收口。

### 2. 工具条组件

`src/editor/media/TableToolbar.tsx`（已存在，继续演进）：

- 挂载在 `NoteEditor` 里，与 `EditHost` 并列
- 目标：当前表格的 `<table>` 元素 + 选区所在单元格
- 命令：`prosemirror-tables` 的 `addRowBefore/After`、`deleteRow`、`addColumnBefore/After`、`deleteColumn`、`mergeCells`、`splitCell`
  - 执行前把选区放到目标单元格：`view.posAtDOM(cell, 0)` + `TextSelection.near`
  - 触屏没有鼠标目标时，直接用当前选区
- 表格外点一下 → 选区离开 → 组件卸载

### 3. 左侧菜单加「表格」分组

BlockNote 的 `SideMenuController` 支持整体替换：

```tsx
<SideMenuController sideMenu={CustomSideMenu} />

// CustomSideMenu = ({ dragHandleMenu }) => <SideMenu>
//   <DragHandleButton />
//   <DragHandleMenu>
//     <BlockColorsItem>颜色</BlockColorsItem>
//     {isTable ? <TableMenuItems /> : null}
//     <RemoveBlockItem>删除</RemoveBlockItem>
//   </DragHandleMenu>
// </SideMenu>
```

已确认可用的导出：`SideMenuController`、`SideMenu`、`DragHandleButton`、`DragHandleMenu`、`BlockColorsItem`、`RemoveBlockItem`、`TableRowHeaderItem`、`TableColumnHeaderItem`。

自定义项用 `DragHandleMenuItem` 渲染，命令与工具条共用同一个 hook，避免两套逻辑。

### 4. 尺寸选择器

- 读当前 `rows × columns`
- 网格：最大 10×10 可点选，超过用输入框
- 应用：`addRowAfter` / `deleteRow` / `addColumnAfter` / `deleteColumn` 循环到目标数量（从末尾增删，保持已有内容不动）
- 缩小到比现有内容少时，弹确认

### 5. 对齐（待验证）

BlockNote 的表格单元格是 `tableCell` 节点，props 里有 `textAlignment`。
两条路：

- A：`editor.updateBlock` 逐格改 props（简单，但单元格多时事务多）
- B：直接用 PM 事务批量改 cell 的 `textAlignment` 属性（快，需确认属性名）

实施前先写一个探针确认属性名，再定方案。

## 八、风险

1. **`.bn-table-handle` 的残留**：上一轮实测 `handles: 2` 仍在，需要逐一确认它们是不是 resize/cell handle，避免把"列宽拖拽"一起屏蔽掉。
2. **对齐属性名待验证**：如果 BlockNote 不把 `textAlignment` 暴露给表格单元格，需要换实现（或不做列对齐）。
3. **尺寸缩小是破坏性的**：必须二次确认，且不能撤销跨多次事务——建议把连续增删合并成一次事务。
4. **`display:none` 掉 BlockNote 的控件**属于"和上游实现耦合"，BlockNote 升级时选择器可能变。缓解：把选择器集中在一个文件里，并留一张回归截图。

---

## 九、不做的

- 右键菜单（成本高，收益低）
- 拖拽排序行列（BlockNote 原生已支持，屏蔽浮钮后可能失效，需要单独评估是否保留）
- Markdown 源码模式的表格编辑（我们是块编辑器，不适用）

## 十三、继续打磨（第二轮）

| 项 | 结论 |
|---|---|
| 列宽是否持久 | **本来就存得住**：拖 120 → 179，`columnWidths: [180, null, …]` 落库，刷新后仍 179 ✅ |
| 选中本行 / 选中本列 | 新增菜单项，走 `CellSelection.rowSelection` / `colSelection` |
| 弹层遮住表格 | 上方空间够（>240px）就朝上弹，并加 `max-height` 防跑出视口 |

### 修掉的三个问题

1. **`⋯` 用取反开关**：命令执行后状态和显示会打架，菜单点不开。改成幂等打开 + `pointerdown` 点外部关闭。
2. **`posAtDOM` 拿不到单元格位置**：`selectRowOrColumn` 一开始用 `view.posAtDOM(cell, 0)`，`selectedCells` 始终是 0。改用 `state.selection.$from` 向上找 `tableCell`。
3. **列合并会把整张表并成一块**：选区覆盖到已合并的整行后，`mergeCells` 按外接矩形合并。加保护：列内存在跨列单元格就拒绝操作。

### 实测

```
3×3 干净表
选中本行 → 合并   第 2 行变成单格 c3（colspan=3）
选中本列 → 合并   中列变成单格 r3（rowspan=3），其余行少一格
列表拖宽          120 → 179，刷新后仍 179
```

### 视觉上的两处收口

- 合并选区的 `::after` 从 BlockNote 的淡蓝 `#c8c8ff66` 换成 `color-mix(in srgb, var(--seal) 14%, transparent)`
- 列宽拖拽线从 `#adf` 换成印章色、宽 2px

### 本轮修掉的 bug 汇总

| 现象 | 原因 | 修法 |
|---|---|---|
| `⋯` 命令后菜单点不开 | 用 `setMenuOpen(v => !v)`，命令后状态和界面不同步 | 幂等打开 + `pointerdown` 点外部关闭 |
| 选中本行/本列没反应 | `posAtDOM(cell,0)` 拿到的位置不在单元格内 | 改用 `state.selection.$from` 向上找 `tableCell` |
| 列合并把整表并成一块 | 选区覆盖已合并的整行，`mergeCells` 按外接矩形合并 | 列内有跨列单元格时直接拒绝 |

## 十四、表格多选 + 工具条宽度

### 工具条宽度改成跟随「表格块」

原来按 `<table>` 量宽度，2 列的窄表只有 622px，工具条就缩成一条短条。现在按 `[data-content-type="table"]`（含内边距的块）定宽：

```
表格宽度 622  块宽度 668  工具条宽度 668  左缘偏差 0
```

### 表格多选

- 入口：表格工具条 `⋯` → 「多选表格…」（当前表自动预选）
- 点任意表格块 = 勾选/取消，选中项用覆盖层画印章色框（不依赖 BlockNote 的块结构，滚动重排都跟得上）
- 底部浮条：`已选 N 张表格 ｜ 合并表格 ｜ 表头行 ｜ 表头列 ｜ 退出多选`

### 批量化

| 操作 | 行为 |
|---|---|
| 表头行 / 表头列 | 以第一张表的状态为准取反，应用到所有选中表 |
| 合并表格 | 按文档顺序把第 2..N 张的行追加到第一张后，列数补到最大值，表头沿用第一张，其余表块删除 |

### 实测

```
3 张表（2 列 / 2 列 / 3 列）
进入多选 → 已选 1 张
```

## 十六、修：拖选多格后批量对齐无效

**现象**：拖选几个表头单元格，点 `≡左`，只有最后悬停的那一格对齐，其他没反应。

### 两个叠加的原因

1. **`instanceof CellSelection` 恒为 false**
   BlockNote 用的是 `prosemirror-tables` 的 **STC 分支**，类不是同一个模块实例，`instanceof` 永远不成立。所以代码一直走"按单列对齐"的分支，等于只处理最后悬停的那一列。
   改成结构性判断：

   ```ts
   export function isMultiCellSelection(sel: unknown): boolean {
     const s = sel as { $anchorCell?: unknown; from?: number; to?: number };
     return s.$anchorCell !== undefined && typeof s.from === "number" && typeof s.to === "number" && s.from !== s.to;
   }
   ```

2. **`from` / `to` 不是首尾单元格的边界**
   判断出是跨格选区后用 `nodesBetween(from, to)` 取格子，实测只命中最后一格（三个格子的选区 `from=28, to=33`，跨度只有 5）。
   `CellSelection` 自带 `forEachCell((node, pos) => …)`，用它拿选区里的每一格：

   ```ts
   const sel = state.selection as { forEachCell?: (f: (n, pos) => void) => void };
   if (typeof sel.forEachCell === "function") sel.forEachCell((node, pos) => hits.push({ pos, node }));
   ```

### 实测

```
表头 4 格，拖选前 3 格 → 点 ≡右
  前：left|left|left|left
  后：right|right|right|left      ← 选区外不动

两行两列选区（4 格）→ 点 ≡中
  第 2、3 行前两列都变 center，其余保持

合并回归（拖选两格 → 合并）：第 3 行前两格合并成 c2 ✅
```

`tsc` 干净、`vitest` 136 项、QA 9/9 + 6/6 全过。

## 阅读模式的表格排版（2026-11-01）

**症状**：笔记里的表格在阅读模式下被撑得很宽，底下带一根横向滚动条；三列的长文表格也一样，右边还露出一片空格子。

**原因**：阅读器的表格用的是 `width: max-content` —— 它按「不折行时的自然宽度」把表格撑开，
所以只要有一格是长句，表格就比正文栏宽，横向滚动条必现；空列再一叠加，看起来就是「一屏空格子」。

**市面最常见的做法**（GitHub 的 markdown 表格、Obsidian 阅读视图、Notion 的表格块都是这一套）：

| 规则 | 值 | 为什么 |
|---|---|---|
| 表格填满正文栏 | `width: 100%` | 表格不该比正文栏宽；内容按比例分配列宽 |
| 内容折行 | `overflow-wrap: anywhere` | 长句 / 长网址断行而不是撑宽表格 |
| 每列最小可读宽度 | `min-width: calc(var(--cols) * 5.5em)` | 列多时保证每列还有 ~77px，不被压成一条 |
| 只有真的放不下才滚动 | 外层 `.tableWrap { overflow-x: auto }` | 8 列 × 5.5em = 616px > 360，此时横向滚动是唯一的正解 |
| 表头不折行 | `.th { white-space: nowrap }` | 「数量」这种两字标题不该被挤成竖排 |

**踩到的坑**：`min-width` 加在 `td` 上浏览器**不认**（table-cell 不是普通盒子），必须量在 `table` 上，
所以 `NoteReader` 把列数通过 `--cols` 传给 CSS。自研表格用已有的 `--sparrow-cols`。

**回滚过一次**：最初的修法是「渲染时裁掉末尾空列」——那是隐藏数据，读的人会以为表本来只有三列，
数据侧的问题被渲染掩盖了。已全部回滚（`tableTrim.ts` 删除）。

**没做的**：空列本身是编辑器留下的数据（Tab 到行尾 / 粘贴宽表）。主流编辑器靠「Tab 到最后一格新增一行」
和菜单里的「删除空列」从源头避免，我们现在这两条都没有——属于编辑器侧，单独一轮做。
