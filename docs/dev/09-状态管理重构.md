# 状态管理重构方案

> 本轮只出方案，不动业务代码。
> 结论先给：**先做 B（拆解 + 收敛存储），暂不引入 Zustand**。理由在第五节。

## 二、问题定性

1. **不是「缺库」而是「缺规范」**：四份 store 各写各的，加一个新 store 又要复制一遍监听模板。
2. **状态归属混乱**：`readMode`（UI 偏好）住在 `useDeskPrefs`，`query`/`dateFilter`（也是 UI 状态）住在 `App`，标准不一致。
3. **`App` 仍承担 5 个职责**：路由、数据、保存、面板、渲染树。
4. **没有跨组件的「读写即取」能力**：任何新面板都得从 `App` 一路传 props。

---

## 三、两条路线

### A. 引入 Zustand（约 3KB，无 Provider）

```
src/store/notes.ts     笔记列表、当前笔记、保存状态、CRUD
src/store/ui.ts        view / profilePage / 面板开关 / 搜索词 / 日期筛选
src/store/settings.ts  偏好（合并现有 settings + theme + updateNotice）
src/store/tableSelect.ts 表格多选（从组件文件里搬出来）
```

- 优点：消灭 prop drilling；四个手写 store 收敛成三个；组件里 `useStore(s => s.x)` 直接取
- 代价：要迁移调用点（约 30 处读、20 处写）；**保存链路必须先稳定**（`putNote` + `markSave` 目前耦合在 `App` 里）；启动时序（Tauri 读库）要挪进 store 初始化
- 风险：迁移期双写（store 与本地 state 并存）容易漏；`editor` 实例不进 store 是底线（BlockNote 实例不能跨渲染共享）

### B. 先拆解 + 收敛存储（不引库）

1. **拆外壳**：把 `App.tsx` 的两套渲染树拆成 `DesktopShell` / `NarrowShell`，`App` 只做编排（目标 ≤400 行）
2. **收敛 store 手艺**：抽一个 `createStore<T>(init)` 工厂（20 行，内部仍是 `useSyncExternalStore`），把四份手写模板替换掉
3. **统一命名与归属**：`src/store/` 下平铺，`useXxx()` 的读写入口统一
4. 之后再评估要不要换成 Zustand（此时迁移面已经很小）

- 优点：零新依赖、每一步可独立验证、`tsc`/测试始终绿
- 代价：`App` 仍然握着数据与路由，跨层级共享还得传 props（但 props 数已明显下降）
- 风险：拆外壳时会碰到两套布局的差异分支（`isNarrow`），要逐屏验

## 四、对比

| 维度 | A Zustand | B 拆解 + 收敛 |
|---|---|---|
| 新依赖 | +3KB | 0 |
| 消灭 prop drilling | ✅ 彻底 | ⚠️ 部分 |
| 迁移风险 | 高（保存链路 / 启动时序） | 中（纯搬迁） |
| 可测性 | store 是纯对象，易测 | 工厂函数易测 |
| 与现有 4 份 store | 要全部重写 | 替换成工厂，语义不变 |
| 一次性收益 | 大 | 中 |

---

## 五、结论与顺序

**先 B，后 A。**

理由：

1. 现在的痛点是「四份复制粘贴」和「App 太大」，不是「缺一个全局 store」。B 直接解决这两点，且零依赖。
2. A 的最大风险在保存链路与启动时序；这些目前都在 `App` 里，**先拆出来才能安全迁移**。B 的第 1 步正好把它拆出来。
3. 拆完之后如果仍觉得跨组件取状态麻烦，再上 Zustand，迁移面只有 `src/store/*`，不再是整个 `App`。

### 分步清单（每步都能独立提交、独立验证）

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | `createStore<T>()` 工厂 + 替换 `theme.ts`（最小的那个） | `tsc` + 主题切换探针通过 |
| 2 | 用工厂替换 `settings.ts` / `updateNotice.ts` / `tableSelect` | 三处行为不变，`vitest` 绿 |
| 3 | 拆 `DesktopShell`：把桌面渲染树搬出去（纯搬迁） | `App` 行数下降、端到端冒烟全过 |
| 4 | 拆 `NarrowShell` | 同上 + 移动端截图对比 |
| 5 | 统一状态归属：`query`/`dateFilter`/面板开关收进 `useUiState()` | props 数再降 |
| 6 | （可选）若仍需要跨层共享，再引入 Zustand，只改 `src/store/*` | 全量回归 |

### 不进 store 的东西（硬约束）

- **BlockNote 的 `editor` 实例**：它是命令式对象，跨渲染共享会出问题；继续用 `useMemo` 在 `NoteEditor` 里持有
- **`notesRef`**：给异步回调读最新值用的 ref，迁移时保留，不要换成 store 读值

---

## 六、风险与回滚

| 风险 | 缓解 |
|---|---|
| 迁移期双写漏状态 | 每步只迁移一个域，迁移完删旧 state；`tsc` 会抓漏改的引用 |
| 拆外壳时两套布局行为漂移 | 端到端冒烟 + 移动端截图对比 |
| store 初始化时序（Tauri 读库） | 保持「`main.tsx` 先画，`App` 里 effect 读库」的现有顺序，不把异步塞进 store 构造 |
| 回滚 | 每步单独提交；B 的每步都是纯搬迁，可 revert 单步而不影响其它 |
