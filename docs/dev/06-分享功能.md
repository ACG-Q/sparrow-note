# 分享功能

阅读页的 `⋯` 菜单里有四项导出：Markdown 单文件、Markdown + 附件 zip、PDF（矢量文字）、长图。

## 入口

桌面（Viewbar 的 `⋯`）和手机（窄屏顶栏的 `⋯`）**共用同一组菜单项**——
抽成了 `src/components/ShareMenuItems.tsx`，样式各自沿用自己那套 `className`。

之前手机上没有，是因为窄屏走的是 App 里另一套顶栏（`isNarrow` 分支），
它的 `popMenu` 里只有「改日期 / 删除笔记」，分享项一个都没挂。


阅读态右上 `⋯`：
- 导出 Markdown（单文件）
- 导出 Markdown + 附件（zip）
- 导出 PDF
- 导出长图 ›（二级：窄 480 / 标准 720 / 宽 960）
- 打印 / 另存为 PDF
- 删除这篇

## Markdown：两种形态

| 形态 | 附件怎么处理 | 文件 |
|---|---|---|
| 单文件 | 内联成 base64 data URL，一个文件拿走全部 | `标题.md` |
| 压缩包 | 落到 `assets/1-pic.png`，正文写相对路径，再打包 | `标题.zip`（内含 `标题.md` + `assets/`） |

序列化在 `src/lib/share.ts`，自己写而不是用 BlockNote 的 `blocksToMarkdown`：
后者要求现成的编辑器实例和 PM schema，而阅读态根本没有编辑器。

覆盖的块：标题（层级）、段落、有序/无序/勾选列表（含子块缩进）、引用、代码块（带语言）、
表格（GFM，竖线转义、自动补空列）、图片/视频/音频/文件/手绘、分隔线，以及
自定义块（`> **心情**：喜` 这种形式，语音块会把音频一起导出）。

## PDF：pdf-lib + 内置中文字体（矢量文字）

自己实现了排版引擎（`src/lib/pdfDoc.ts`），不用 html2pdf 之类——它们最后还是把中文栅格化。

覆盖：标题层级、段落（含粗体/代码底/链接下划线）、列表、引用（左边线）、代码块（底色 + 硬折行）、
**表格（等宽列 + 边框 + 单元格折行 + 跨页重复表头）**、图片、自定义块、分隔线。

### 字体

| 文件 | 覆盖 | 大小 |
|---|---|---|
| `sparrow-sans-sc.ttf` | GB2312 一级 + 二级（7719 字）+ 拉丁 + 标点 | 1.90 MB |
| `sparrow-sans-sc-bold.ttf` | GB2312 一级（4711 字） | 1.13 MB |

粗体是**真的粗体字重**，不是重复绘制模拟——之前用偏移重绘，复制出来是「加加加粗粗粗」。
粗体子集只收一级汉字，遇到缺字自动退回常规体，不会出现空白方框。

生成脚本：`scripts/subset-font.mjs`（`subset-font` + GB2312 码表，构建期一次性跑）。

### 体积

字体和库都是**按需加载**（点导出才拉），不影响首屏：

```
sparrow-sans-sc.ttf       1.94 MB
sparrow-sans-sc-bold.ttf  1.16 MB
pdf-lib                   430 kB（gzip 129 kB）
fontkit                   711 kB（gzip 330 kB）
```

Tauri 打包时这些仍会进安装包，**约 +4.2 MB**。

### 实测

```
单页笔记   408ms，31KB，pdfjs 抽出 85 个字符的中文
长文 70 段  3 页，70KB，抽出文本含「第 1 段」…「第 70 段」，无丢失
长表格 46 行 2 页，两页都有表头「姓名/金额」，最后一行还在
```

### 什么时候还会用到打印

`printNode()` 还留着（`@media print` 样式也在），但菜单里没挂——矢量 PDF 已经覆盖它的用途。

## 打印 / 另存为 PDF

菜单里也保留系统打印这一项：翻页由打印引擎控制（比我们自己切的页更贴 A4 排版），
打印样式里加了 `break-inside: avoid`（图片、表格行、引用、代码块不跨页）、
标题不与下文分离（`break-after: avoid`），并隐藏打印稿里的按钮。

清理时机：`afterprint` → 窗口重新获得焦点 → 30 秒兜底，三重保证不会把页面留在打印态。

## 文件到底怎么交到用户手里

导出最终都要落盘，这里踩过一个坑：**Android WebView 不支持下载 `blob:` 链接**。
`URL.createObjectURL()` + `<a download>` + `a.click()` 在安卓的 WebView 里既不会
产生文件、也不报错——界面只能"假装成功"，用户翻遍手机也找不到导出的东西。

所以保存统一走 `src/lib/saveFile.ts`：

| 环境 | 分支 |
|---|---|
| 浏览器 / 桌面 WebView（Windows、macOS、Linux） | 原来的 `<a download>`（`blob:` 或 data URL） |
| Tauri 移动端（Android / iOS） | `save()` 弹系统「另存为」→ `writeFile()` 真正写盘 |

```ts
const path = await save({ defaultPath: name, filters: [{ name: "MD", extensions: ["md"] }] });
if (!path) return { status: "cancelled" };   // 用户取消，不能当成功
await writeFile(path, bytes);                // 写失败会抛，交给界面报错
```

### 安卓上拿到的是 `content://`，不是路径

`save()` 在安卓走的是 SAF 的 `ACTION_CREATE_DOCUMENT`，返回
`content://com.android.externalstorage.documents/document/primary%3ADownload%2F标题.md`。
不是文件路径，**不能**拼字符串、也不能用 `std::fs` 直接写。

tauri-plugin-fs 认得这种 URL：`SafeFilePath::Url` 分支拿它去
`ContentResolver.openAssetFileDescriptor()` 换 fd，再 `File::from_raw_fd`。
实测能正常写。所以 `writeFile(contentUri, bytes)` 就是正确用法，不用自己写 Kotlin。

> 也因此不需要给 fs 配 `$DOWNLOAD` 之类的 scope：URL 分支不走路径 scope 检查，
> 授权来自系统对话框本身。capabilities 里只要 `dialog:allow-save` + `fs:allow-write-file`。

### 结果契约（提示必须是真的）

`SaveOutcome` 只有三种可能，界面按它说话：

| 结果 | 含义 | 提示 |
|---|---|---|
| `{ status: "saved", via: "tauri" }` | 写盘成功，文件真的在了 | `已保存 标题.md` |
| `{ status: "saved", via: "browser" }` | 下载已发起（浏览器无法进一步确认） | `已开始下载 标题.md` |
| `{ status: "cancelled" }` | 用户点了返回 / 取消 | `已取消保存` |
| 抛异常 | 生成失败或写盘失败 | `导出 PDF 失败：<原因>` |

之前 `exportNotePdf` 的 `.catch()` 是空的、Markdown 导出压根没有提示、
长图提示写死「已导出 N 张图」——现在全部按真实返回值说话。
长图分多张时每张都要过一次「另存为」，中途取消会停下并提示
「已保存 2 张图，其余已取消」。

同一个坑还波及两处，一并改掉：设置页的备份导出、手绘/预览图的「存为图片」。
它们原来也用 `<a download>`，在安卓上同样是静默失败。

| 位置 | 需要什么 |
|---|---|
| `package.json` | `@tauri-apps/plugin-dialog`、`@tauri-apps/plugin-fs`（生产依赖 17 → 19，是"不加运行时依赖"的一次例外：安卓上没有别的办法） |
| `src-tauri/Cargo.toml` | `tauri-plugin-dialog = "=2.8.4"`、`tauri-plugin-fs = "=2.7.1"`，**版本写死**并 `[patch.crates-io]` 指到 `src-tauri/vendor/`（build.rs 被火绒拦，见 `04-打包指南.md`） |

### 模拟器实测（2026-10-31，emulator-5554 / MuMu，API 36）

`npx tauri android build --apk --debug --target x86_64` → `adb install -r` → 阅读态 `⋯` → 各项导出。

| 操作 | 结果 |
|---|---|
| 导出 Markdown | 系统「另存为」默认名 `无标题.md`；保存后 `/sdcard/Download/无标题.md` 36 B，内容是 UTF-8 的 `# 无标题 / > 2026-10-30 / hello-sim` |
| 再导一次 | 提示 `已保存 无标题(1).md`，Download 里真的多出 `无标题 (1).md` |
| 在对话框里按返回 | 提示 `已取消保存`，Download 没有新增文件 |
| 导出 Markdown + 附件 | `无标题.zip` 161 B，头 4 字节 `50 4b 03 04` |
| 导出长图（标准 720） | `麻雀记.png` 29 796 B，`file` 认出 `PNG image data, 1552 x 426 RGBA`，图里中文正常 |
| 导出 PDF | `无标题.pdf` 13 023 B，头 `%PDF-1.7`，pdfjs 抽出 `无标题 / 2026-10-30 / hello-sim` |
| 导出备份（设置页） | 提示 `已导出 1 篇 · 0 个附件：麻雀记-备份-20261031.sparrow`，Download 里 1177 B |
| 清空全部 → 取消 | 数据还在（1 篇） |
| 清空全部 → 清空 | 变 `0 篇`、空态「还没有记录」 |
| 导入备份 | 选包后显示 `1 篇 · 0 个附件 · 包 1.1 KB（解压后 762 B）`，确认后 `写入 1 篇`，时间线回到 1 篇 |

截图证据当时留在临时目录，没有入库。

> 小瑕疵：提示里的文件名是从 `content://` 的 docId 解码出来的，和 DocumentsUI 的真实
> 显示名可能差在空格这类字符（docId 会做一次清洗）。文件名信息仍然是对的，
> 只是偶尔少个空格。

### 备份导入 / 清空在安卓上的两个坑

1. **`<input type="file">` 的 accept 是按 MIME 过滤的**

   桌面上 `accept=".sparrow,.zip,application/zip"` 按扩展名放行；安卓的 DocumentsUI 只认 MIME。
   `.sparrow` 是自家扩展名，系统不认识 → 当成 `application/octet-stream` → **自己的备份文件
   在列表里是灰色的、点不动**（同一个文件改名成 `.zip` 立刻可选，可以这样复现）。
   修法：accept 里补 `application/octet-stream`。放开一点没关系——包结构由 `readPackage()`
   自己校验，选错文件只会得到一句「无法读取备份」。

2. **`window.confirm` 的按钮是英文**

   wry 的 `WebChromeClient.onJsConfirm` 接管了 `window.confirm`，弹的是系统 AlertDialog：
   消息是中文，按钮却固定 `OK / CANCEL`。
   危险操作改走 `src/lib/confirm.ts` 的 `confirmAction()`：移动端用 plugin-dialog 的
   `confirm()`（标题、按钮文案都能写中文，capabilities 要 `dialog:allow-confirm`），
   浏览器和桌面仍用 `window.confirm`，行为不变。

## 长图

SVG `<foreignObject>` 把克隆出来的阅读态 DOM 连同样式一起渲染进 canvas（2 倍图），
不用 html2canvas（1MB+ 且中文排版经常错）。

样式是整站 `document.styleSheets` 复制过去的，CSS Modules 的类名在克隆节点里一致；
`:root` 上的 CSS 变量单独抄了一份（SVG 里没有 `:root` 可匹配）。

## 已知限制

- 生僻字超出 GB2312 二级时，PDF 里可能缺字（子集没收录）
- 单文件里如果有几百 KB 的音频，`.md` 会变得很大（这是内联的代价）
- 外链图片保持原 URL，PDF 里不会去下载
- 表头重复只支持「一行表头」
