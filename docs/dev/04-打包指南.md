# 打包指南（Windows 桌面 + Android）

日期：2026-10-26
适用：本机环境（Windows 11 / Rust 1.95 / Node 24 / Android SDK `D:\dev\Android\Sdk`）

## 桌面端

```powershell
npm run tauri build
```

产物：

| 文件 | 大小 | 说明 |
|---|---|---|
| `src-tauri/target/release/sparrow-note.exe` | ~12.7 MB | 免安装单文件 |
| `src-tauri/target/release/bundle/nsis/sparrow-note_0.1.0_x64-setup.exe` | ~3.8 MB | NSIS 安装包 |

数据库在 `%APPDATA%\com.sparrow.note\notes.db`（用户数据目录），WebView 数据在 exe 旁边的 `webview-data/`。

数据库位置按**构建阶段**决定（`db_conn_url()`）：

| 阶段 | 构建 | 库放哪 |
|---|---|---|
| 开发 | `npm run tauri dev`（debug 构建） | exe 旁边（`src-tauri/target/debug/notes.db`），调试时不用翻 AppData |
| 安装运行 | `npm run tauri build`（release 构建） | `%APPDATA%\com.sparrow.note\notes.db`，装到 Program Files 这种只读目录也能存 |
| 移动端 | 同上 release | 应用私有目录 `/data/user/0/com.sparrow.note/notes.db` |
| 浏览器 | `npm run dev` | IndexedDB `sparrow-note` |

判断依据是 `cfg!(debug_assertions)`，不是运行时探测。另有两道保险：

- `dir_writable()` 会**真的写一个探针文件**试探（只读目录上 `create_dir_all` 也可能“成功”而写文件失败）；
  首选位置写不进就换另一个再试一次。
- `migrate_legacy_db()`：从 exe 旁的库搬到 AppData 时会连 `-wal` / `-shm` 一起搬，不丢数据。

> 本机验证（2026-10-26）：
> debug 版跑起来库在 `target\debug\notes.db`；把 release 版放进 `D:\Software\sparrow-note` 跑，
> 库落在 `%APPDATA%\com.sparrow.note\notes.db`，exe 旁边干净。
>
> 关于安全软件：火绒的 HIPS 会拦「非安装目录里的程序」写 `%APPDATA%`（`target\`、`%TEMP%` 里跑就被拒），
> 装好的位置不受影响。所以开发阶段用 exe 旁边，正好绕开这个坑。

设置页的「存储」一栏会显示当前的数据库路径（来自 `get_sqlite_url` 命令），可一键复制。

> 另外：打出来的 `sparrow-note_0.1.0_x64-setup.exe` 是**未签名**的，本机静默安装（`/S`）会被拦下——
> 退出码 0 但什么都没装。手动双击安装、或给安装包签名，才能装。


## Android

### 需要的环境（每次构建都要设，不需要改系统环境变量）

```powershell
$env:JAVA_HOME     = "D:\dev\Android\.jdks\ms-17.0.19"   # 必须是 JDK 17+
$env:ANDROID_HOME  = "D:\dev\Android\Sdk"
$env:ANDROID_SDK_ROOT = "D:\dev\Android\Sdk"
$env:NDK_HOME      = "D:\dev\Android\Sdk\ndk\28.2.13676358"   # 必须是 NDK 28+
$env:PATH = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
```

Rust 侧需要装过的目标：

```powershell
rustup target add aarch64-linux-android x86_64-linux-android armv7-linux-androideabi i686-linux-android
```

### 命令

```powershell
npx tauri android init --ci --skip-targets-install   # 只在第一次，生成 src-tauri/gen/android
npx tauri android build --apk --split-per-abi        # release，按 ABI 分包
npx tauri android build --apk --debug --target x86_64 # 调试包（可 adb install，模拟器用）
```

产物（`src-tauri/gen/android/app/build/outputs/apk/`）：

| 文件 | 大小 | 用途 |
|---|---|---|
| `arm64/release/app-arm64-release-unsigned.apk` | ~15 MB | 主流手机 |
| `arm/release/app-arm-release-unsigned.apk` | ~11.6 MB | 老 32 位机 |
| `x86_64/release/app-x86_64-release-unsigned.apk` | ~14.5 MB | 模拟器 |
| `universal/debug/app-universal-debug.apk` | ~33 MB | 调试用，Gradle 自动签名 |

> release APK 是**未签名**的，上架或分发前要用自己的 keystore 签一次。

### 本机踩到的四个坑（都已处理，换机器注意）

1. **火绒拦截编译脚本写 cargo 缓存**
   `tauri-plugin-geolocation` 的 `build.rs` 会往 `CARGO_MANIFEST_DIR/android/.tauri` 复制文件，
   而 cargo 把依赖源码放在 `C:\Users\LiuJi\.cargo\registry\...`，火绒的 HIPS 拒写 → 报
   `failed to create .tauri directory: 拒绝访问 (os error 5)`。
   处理：把插件复制进项目 `src-tauri/vendor/tauri-plugin-geolocation`，并在 `src-tauri/Cargo.toml`
   用 `[patch.crates-io]` 指过去，写入就发生在项目目录内。

2. **Gradle 发行版下载被掐断**（SSL reset，下到 1.6 MB 就断）
   处理：`src-tauri/gen/android/gradle/wrapper/gradle-wrapper.properties` 的 `distributionUrl`
   改成腾讯镜像 `https://mirrors.cloud.tencent.com/gradle/gradle-9.6.1-bin.zip`，并加 `networkTimeout=120000`。

3. **NDK 版本：必须 28+**
   NDK 27 编出来的 `.so` 是 4 KB 对齐，安装到 Android 15/16 会弹「不符合 16 KB 对齐要求」。
   NDK 28 默认按 16 KB 对齐。

4. **移动端专属代码**
   - `db_conn_url` 在移动端用 `app_data_dir()`（exe 目录在安卓上是只读的应用包）；
     桌面仍用 exe 旁目录（本机安全软件按镜像路径拦 %APPDATA%）。
   - 日志插件、`webview-data` 目录、手动建窗口都只在 `#[cfg(desktop)]` 下执行；
     移动端窗口由 `#[cfg(not(desktop))]` 分支创建（配置里 `create: false`，桌面要自己控制数据目录）。
   - `tauri-plugin-mcp-bridge` 只在桌面存在（它调用了安卓上不存在的 `WebviewWindow::minimize/maximize`），
     依赖和 `capabilities/mcp-dev.json` 都按平台限定。

### 在模拟器里跑

```powershell
$adb = "D:\dev\Android\Sdk\platform-tools\adb.exe"
& "D:\dev\Android\Sdk\emulator\emulator.exe" -avd Medium_Phone_API_36.1 -no-boot-anim
& $adb install -r src-tauri\gen\android\app\build\outputs\apk\universal\debug\app-universal-debug.apk
& $adb shell am start -n com.sparrow.note/.MainActivity
```

应用私有目录（`run-as` 可看）：`/data/user/0/com.sparrow.note/notes.db`。

## 状态栏 / 底部手势条

应用是 edge-to-edge（`MainActivity` 里调了 `enableEdgeToEdge()`），内容默认会画到状态栏和导航栏底下，
顶栏会和状态栏的时间、电量叠在一起。

处理方式（`gen/android` 里，两个文件）：

1. `app/src/main/java/com/sparrow/note/MainActivity.kt`
   给根视图（`android.R.id.content`）挂 `setOnApplyWindowInsetsListener`，把
   `systemBars + displayCutout` 的 insets 当作 padding 让出来。
2. `app/src/main/res/values/themes.xml` 与 `values-night/themes.xml`
   把 `android:windowBackground` 设成日间纸 `#f5f1e8` / 夜间墨 `#141311`，
   让出来的那条区域就显示这个颜色；状态栏和导航栏本身设成透明。

> 已知限制：这条底色跟的是**系统**的日/夜间（`values-night`），不是应用内选的主题。
> 所以在系统日间、应用内手动选「夜间纸」时，顶部那条会是纸色。
> 要彻底一致，需要把应用内主题通过 JS→Kotlin 通道同步给 Activity（同时翻转
> `isAppearanceLightStatusBars`，否则图标会看不清），这一步还没做。

> 注意：`src-tauri/gen/` 被 .gitignore 忽略，上面两处改动不进仓库；
> 重新 `tauri android init` 之后要再改一次。
