# 设置页与数据存储

页面：`src/SettingsView.tsx`（我的 → 设置）。数据位置：`src-tauri/src/storage.rs` +
`src/lib/storageInfo.ts`。自动备份：`src/lib/backups.ts`。

## 页面结构（2026-10 重排）

原来的「存储 / 地图 / 数据」三块是把「看路径」和「导出导入」拆开的，用起来要在页面上来回找。
现在合并成一个「数据与存储」，顺序按「先看、再设、最后是危险操作」：

```
数据与存储
  用量           1 篇笔记 · 0 个附件
                 正文 222 B · 附件 0 B · 合计 222 B
  数据库         /data/user/0/com.sparrow.note/notes.db      [复制路径]
                 SQLite 单文件 · 占用 20 KB
  存放位置       [应用私有目录 · 当前使用中]
                 [应用外部目录]
  [✓] 自动备份   …
  立即备份
  ── 导入导出 ──
  [导出备份] [导出仅文字] [导入备份]
  ── 危险操作 ──
  [清空全部]
  清空后不可撤销，建议先「立即备份」或「导出备份」。
地图
  高德地图 ✓
```

要点：

- **用量**用和导出同一套转换（`noteToCanonical` + `AssetSink`）算，不另写「哪些字段算附件」的规则
  ——那种规则一定会和导出慢慢跑偏。附件按内容去重，所以「12 个附件」和备份包里的附件数一致。
- 自动备份关掉时，频率和保留份数直接不显示（不摆一堆用不上的控件）。
- 操作按「日常（导入导出）/ 危险（清空）」分组，按钮不再混在一排里；
  执行结果用一条带左侧色条的状态行说清楚，不再挤在按钮右边。

## 换数据存放位置（桌面 + 安卓都能换）

数据库位置原本在编译期定死（debug 在 exe 旁、release 在 `%APPDATA%`）。现在多了一层：

| 平台 | 可选位置 |
|---|---|
| 桌面 | 默认位置 + 系统目录选择器挑任意目录 |
| 安卓 | 应用私有目录 / 应用外部目录 / **「选择位置…」用系统文件夹选择器挑任意文件夹**（需要「所有文件访问」权限） |
| iOS | 只有应用私有目录 |
| 浏览器 | IndexedDB，浏览器托管 |

用户选择写在 `app_config_dir()/storage.json` 的 `data_dir`（Windows：`%APPDATA%\com.sparrow.note\storage.json`）。

### 安卓上「选文件夹」是怎么实现的

`tauri-plugin-dialog` 在移动端**不实现**目录选择器（Rust 侧直接返回 `FolderPickerNotImplemented`），
所以自己写了一个最小插件 `src-tauri/plugins/tauri-plugin-sparrow-storage`：

| 命令 | 作用 |
|---|---|
| `pick_folder` | `ACTION_OPEN_DOCUMENT_TREE` 选文件夹；把 SAF 的树 URI 换算成真实路径（`primary:Documents` → `/storage/emulated/0/Documents`），并 `takePersistableUriPermission` |
| `storage_access` | 查 `MANAGE_EXTERNAL_STORAGE`（所有文件访问）是否已授权 |
| `request_storage_access` | 跳到系统的那一页去授权 |

为什么要这个权限：SQLite 只认真实路径，而安卓 11+ 要把文件写到「内部存储 / 存储卡」的任意目录，
必须有「所有文件访问」；没授权时 `pick_folder` 仍会把 `allFiles=false` 带回来，界面引导去打开，
期间用户还能用「应用私有 / 应用外部」两个固定位置。

> 早期版本还留了一条「移动端只放行候选目录」的白名单，结果「选择位置…」挑的文件夹被自己拦掉，
> 报 `这个目录不允许`。现在只要求**绝对路径**，能不能写交给 `dir_writable` 实测。

### 切换流程

1. `prepare_data_dir`：后端校验目录（是否允许、可写、里面有没有旧库）；
   已有旧库时先返回 `needsConfirm`，**不直接覆盖**；
2. 用户确认后带 `force` 再来一次：旧库改名成 `notes.db.bak-<时间戳>`（连 `-wal` / `-shm` 一起挪，
   免得旧 WAL 被应用到新库上），然后才写新库；
3. `VACUUM INTO '<新目录>/notes.db'` —— SQLite 自己的一致性快照，不是复制文件
   （WAL 里可能还有没合并的写入）；
4. `set_data_dir` 只写配置；
5. `restart_app`：桌面会真正重启；**安卓没有 re-exec，等于退出应用**，界面上提前写明「重新打开后生效」。

安全绳：

- **原位置的库不删**。改回默认只是切回去，两边各留一份。
- 自定义目录写不进去时 `db_conn_url()` 自动回落默认位置并打一行 stderr，应用不会因为配置坏了起不来。
- 配置 JSON 坏掉同样按「用默认位置」处理。
- 目录校验放在 Rust（`std::fs`）而不是前端 fs 插件：fs 插件查文件要过 scope，
  应用外部目录不在 AppData 作用域里，会被判成 `forbidden path`（踩过）。


## 自动备份

| 项 | 值 |
|---|---|
| 位置 | `app_data_dir()/backups/`（Windows `%APPDATA%\com.sparrow.note\backups`，安卓 `/data/user/0/com.sparrow.note/backups`） |
| 文件名 | `sparrow-20261031-201533.sparrow` |
| 频率 | 每次启动 / 每天 / 每周（`backupDue()` 纯函数，可单测） |
| 保留 | 3 / 5 / 10 份，超出的删掉 |
| 触发 | 应用启动后 `maybeAutoBackup(notes)` 跑一次；同一次启动只跑一次 |
| 浏览器 | 没有可写的本地目录 → 开关禁用，只能手动「导出备份」 |

为什么不用系统「另存为」对话框：自动备份不能每次都让人点两下。应用私有目录一直可写，
`fs` 插件的 AppData 作用域就够（`fs:allow-appdata-{read,write}-recursive`），不用申请存储权限。
