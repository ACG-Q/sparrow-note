# 13 · CI 与发版

## 一个文件跑完三种事

所有 CI 都在 `.github/workflows/ci.yml`，靠触发器和 job 级 `if` 分流：

| 触发 | 跑什么 |
|---|---|
| 推 `main`/`master`、开 PR | `web`（tsc / oxlint / vitest / 覆盖率）+ `rust`（`cargo test --lib` + `cargo check --all-targets`） |
| 推 `v*` tag | `desktop`（三平台）+ `ios` + `android` 并行打包，各自只上传 artifact；最后由 `publish` 一次性发到同一个 Release |
| 手动 Run workflow | 三端都打包，只出 artifact、不发版（谁先跑完谁的 artifact 先能下） |

同一 ref 上新的推送会取消上一轮（tag 发版不取消，避免发一半）。
只改文档（`docs/**`、`review/**`、`**/*.md`、`.gitignore`）不触发。

为什么不拆成三个 yml：本质上只有「门禁」和「发版」两种意图，而 job 级 `if` 已经把它们分开了；
拆开的话 action 版本、Node 版本、Linux 依赖要抄三遍，改一次得改三处。
**上传只有一个出口**：`desktop` / `ios` / `android` 三个 job 都只负责打包 + 上传 artifact，
Release 的名字、说明、prerelease 判断和资产上传全部集中在 `publish` job（`softprops/action-gh-release`）。
好处是：不会出现几个 job 抢着建 Release、也不会出现「桌面包已经挂上去、移动端还没传」的半成品状态；
想改发布说明只改一处。

## 打包细节

- 矩阵：Windows x64、macOS Apple Silicon（`--target aarch64-apple-darwin`）、Linux x64。
- Linux 需要 Tauri 的系统依赖：`libwebkit2gtk-4.1-dev`、`libgtk-3-dev`、`librsvg2-dev`、`libayatana-appindicator3-dev`、`patchelf`。
- 没配签名密钥，所以**不开 updater 清单**（`includeUpdaterJson` 保持默认关闭）；
  「检查更新」走的是 GitHub Release 的公开 API，不需要签名。
- 安卓只给**调试包**（手动触发），不签名；正式安卓包仍按 `docs/dev/04-打包指南.md` 在本地打。

## 「检查更新」指向远程仓库

原来默认是 `manifest` 源 + 空地址，页面显示「未配置」。现在：

1. `package.json` 加 `repository`，写 `git+https://github.com/<owner>/<repo>.git`；
2. `src/lib/repo.ts` 从这一处解析出 `owner/repo`（支持 `git+https`、`github:`、完整地址、`owner/repo` 等写法）；
3. `src/lib/updates.ts` 的默认值改成 `source: "github"` + 该仓库；
4. 老用户存过的「空地址 + 空仓库」按「从没配置过」处理，自动迁到新默认；自己配过的（填了地址或换了仓库）一律不动。

于是发版流程就是：**打 `v0.2.0` 这样的 tag → 工作流出包含 Release → 应用里点「检查更新」看到新版本**。

> tag 必须是纯版本号（`v0.2.0`）。像 `tauri-cli-v2.12.4` 这种前缀 tag 读不出版本，页面会明确提示。

## 换仓库怎么办

只改 `package.json` 的 `repository` 一处。界面上也还能改（关于 → GitHub 仓库），那是本机覆盖，不会进版本库。

```
npm run lint       → 0 warnings / 0 errors（232 文件）

```

- 「检查更新」用真实 GitHub API 跑通过：把仓库临时改成 `microsoft/vscode`，页面显示「有新版本 1.144.0」、

## 移动端（安卓）怎么打包

`android` job 和其它打包 job 并行，产物先落到 artifact，最后由 `publish` 统一发。

1. JDK 17 + `android-actions/setup-android`，接受 SDK 许可后由 Gradle 自己下 platform / build-tools / NDK；
2. Rust 装 `aarch64-linux-android`、`armv7-linux-androideabi`、`x86_64-linux-android` 三个目标；
3. `npx tauri android build --apk` → `universal/release/app-universal-release-unsigned.apk`（release 包默认未签名）；
4. 有 keystore 就签：

```bash
zipalign -p -f 4 app-universal-release-unsigned.apk aligned.apk
apksigner sign --ks release.jks --ks-key-alias "$KEY_ALIAS" \
  --ks-pass "pass:$KS_PASS" --key-pass "pass:$KEY_PASS" --out sparrow-note-<版本>-universal.apk aligned.apk
apksigner verify --print-certs sparrow-note-<版本>-universal.apk
```

5. 没配 keystore 就退回 `--debug` 包（Gradle 用 debug key 自动签名，能直接装），文件名带 `-debug`——
   这样「移动端也出了包」不会因为少一个 secret 整条流水线红掉。

需要的 secrets：

| Secret | 说明 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 release.jks` 的结果 |
| `ANDROID_KEYSTORE_PASSWORD` | 仓库口令 |
| `ANDROID_KEY_ALIAS` | key 别名 |
| `ANDROID_KEY_PASSWORD` | key 口令 |

生成 keystore（一次性，**务必备份**——丢了就没法给同一个包升级）：

```bash
keytool -genkeypair -keystore release.jks -alias sparrow -keyalg RSA -keysize 2048 \
  -validity 10000 -storepass <口令> -keypass <口令> -dname "CN=Sparrow Note"
base64 -w0 release.jks   # 贴进 ANDROID_KEYSTORE_BASE64
```

### 本机验证过的部分

- `zipalign → apksigner sign → apksigner verify` 这条链路在本机跑通（用临时 keystore 签了调试包，
  `verify --print-certs` 能打出证书 DN 和 SHA-256）。
- 踩到一个坑：Windows 上 `apksigner.bat` 会自己 `cd` 到 build-tools 目录，**相对路径会失效**，
  必须传绝对路径（CI 在 Linux 上用 `$PWD/dist/...` 与 `$RUNNER_TEMP/...`，没问题）。

### 没做的

- **iOS 没接**：项目没有 `gen/apple`，也没有苹果开发者证书，无从打包。
- 安卓 job 只在 GitHub 上跑过（本地只验证了签名链路和 `--apk` 的产物路径），
  第一次跑真实 Actions 时留意 Gradle 自动下载 SDK 组件那一步的网络耗时。

## iOS / IPA：为什么这里打不出来

`npx tauri ios` 在 Windows 上**没有这个子命令**（本机实测：`unrecognized subcommand 'ios'`），
而且仓库里没有 `src-tauri/gen/apple`。iOS 编译链只有 macOS + Xcode 有，所以 IPA 只能从：

- 一台装了 Xcode 的 Mac，或
- GitHub Actions 的 `macos-latest` runner（`ci.yml` 里的 `ios` job）

出来。

### 光「能打包」还不够：装到 iPhone 上必须有苹果签名

| 情况 | 结果 |
|---|---|
| 有 Apple Developer（$99/年）+ 分发证书 + 描述文件 | `tauri ios build --export-method ad-hoc` 出 `.ipa`，能直接装 |
| 只有免费个人团队 | 只能在**连着的真机**上由 Xcode 签名安装，7 天过期；出不了可转发的 IPA |
| 什么都没有 | 只能出一个未签名的 `.app`/`.ipa` 壳，iPhone 上装不了（要别人用 AltStore/Sideloadly 用自己的 Apple ID 重签） |

CI 里用到的环境变量（Tauri 官方文档的定义）：

| Secret | 说明 |
|---|---|
| `IOS_CERTIFICATE` | `.p12` 的 base64（`base64 -i cert.p12`） |
| `IOS_CERTIFICATE_PASSWORD` | 导出 .p12 时设的密码 |
| `IOS_MOBILE_PROVISION` | `.mobileprovision` 的 base64 |

没配这三个时，`ios` job 只做两件事：`tauri ios init` 生成工程 + `cargo build --lib --target aarch64-apple-ios`
验证 Rust 能编到 iOS（不出 IPA，因为出了也装不上）。

### 为 iOS 顺手修的一个编译错误

自研插件 `tauri-plugin-sparrow-storage` 原来用 `cfg(mobile)` 门控，里面却调
`api.register_android_plugin(...)`——这个 API 只有安卓目标才有，**给 iOS 编译会直接失败**。
现在全部改成 `cfg(target_os = "android")`，iOS 上三个命令返回「iOS 上不支持选目录，请用导出备份」。

### 还没做的（真要上 iPhone 必须先过这些）

1. **签名**：需要你的 Apple Developer 账号（我这边没有）；
2. **iOS 工程**：`gen/apple` 还没生成过，第一次在 macos runner 上跑 `tauri ios init` 才知道有没有坑；
3. **iOS 功能适配**：数据目录只落在应用沙箱（`pick_folder` 已明确拒绝）、导出走系统的「文件」App、
   通知/定位插件的 iOS 权限文案与 Info.plist 声明都还没配。

> `ios` job 我无法在本机验证（没有 macOS/Xcode），第一次跑 Actions 时当作「试编译」看待。

### 不签名、只出 `.ipa` 文件（可行，有前提）

结论：**能出文件，但这台 Windows 出不了**——iOS 编译链（Xcode + Apple 工具链）只有 macOS 有，
`npx tauri ios` 在 Windows 上连子命令都不存在（实测 `unrecognized subcommand 'ios'`）。

未签名 IPA 的本质就是「`.app` 目录压成 zip、外面套一层 `Payload/`」：

```bash
# 1) 生成 iOS 工程（一次就行，gen/apple 不入库）
npx tauri ios init

# 2) 关掉签名，只 build 不 export
cd src-tauri/gen/apple
xcodebuild -project <App>.xcodeproj -scheme <App> \
  -configuration release -sdk iphoneos \
  -derivedDataPath "$PWD/build" \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY="" CODE_SIGN_ENTITLEMENTS="" \
  build

# 3) 打包成 ipa
mkdir -p Payload
cp -R build/Build/Products/Release-iphoneos/<App>.app Payload/
zip -qry sparrow-note-unsigned.ipa Payload
```

> 带 Pods 的工程要用 `-workspace <App>.xcworkspace` 代替 `-project`；
> scheme 名用 `xcodebuild -list` 看。

CI 里已经这么做了：`ci.yml` 的 `ios` job 在**没配签名 secrets** 时走这条未签名路径，
产物是 `sparrow-note-<版本>-ios-unsigned.ipa`，上传 artifact 并挂到 Release。

**这种 ipa 能干什么**：越狱设备可以直接装；普通 iPhone 需要用 AltStore / Sideloadly / TrollStore
之类的工具，拿自己的 Apple ID（免费 7 天，或开发者账号 1 年）重签后再装。
签名那一步不在文件里，所以「提供一个 ipa 就给谁都能装」在 iOS 上不成立——这是苹果的机制，不是打包方式的问题。

## 「一键只出 IPA」

Actions → **CI** → Run workflow（`workflow_dispatch`），不需要任何 secrets。
`desktop` / `ios` / `android` 三个 job **并行**跑，`ios` 一般最先完成，
artifacts 里就能下 `ios-ipa` → `sparrow-note-<版本>-ios-unsigned.ipa`。

（早先拆过一个独立的 `ios-ipa.yml`，为的是绕开「ios 要等桌面包」；
现在 `ios` 不再 `needs: desktop`，独立文件就没必要了——包全部由 `publish` job 在最后统一上传。）

### 为什么这一步得在 GitHub 上跑

本机这台 Windows：

| 项 | 状态 |
|---|---|
| `npx tauri ios` 子命令 | 不存在（`unrecognized subcommand 'ios'`） |
| Xcode / Apple 工具链 | 没有（Windows 上不可能有） |
| `git remote` | 没配（`git remote -v` 空） |
| `gh` CLI | 没装 |

所以「改 action」这件事已经做完了（文件在仓库里，逻辑齐全），缺的是
**把代码推到 GitHub 并点一次 Run workflow**——这一步在本机做不到。

推上去只要四条命令（在仓库根目录）：

```bash
git remote add origin https://github.com/<你>/<仓库>.git
git add .github src package.json package-lock.json docs
git commit -m "ci: 质量门禁 / 发版 / 未签名 IPA 工作流"
git push -u origin main
```

推上去后：仓库 → Actions → 左侧「生成未签名 IPA」→ Run workflow → 等 macOS runner 跑完 → 下载 artifact。

> 如果之后的 `tauri ios init` 或 scheme 发现在 runner 上报错（我无法在 Windows 上预演这一步），
> 把日志贴给我，我按报错改脚本；这一步通常是一次性的。
