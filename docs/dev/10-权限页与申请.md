# 权限页与「申请权限」

页面：`src/PermissionsView.tsx`（我的 → 权限），逻辑：`src/lib/permissions.ts`。

这一页只做两件事：**检测**当前状态、**发起申请**。系统层面的开关（Windows 隐私设置、
Android 应用权限页）不归它管，被拒绝时给出去哪儿打开。

## 页面结构

```
← 我的
权限                                    Android
──────────────────────────────────────────────
麻雀记不需要账号，也不上传内容……
┌───────────────────────────────────┐
│ 2 项待授权                         │  ← 汇总：还剩几件事
│ 已允许 4                           │
│ [ 全部申请（2） ] [ 重新检测 ]      │  ← 批量申请 / 整页重探
└───────────────────────────────────┘
位置                            [已允许]   ← 状态方章
给笔记打上「我在哪」的坐标，再反查地名
位置块 · 使用当前位置
麦克风                          [待授权]
…
[ 申请权限 ]                               ← 只有还能申请的行才有按钮
╎ 已允许，现在可以用了。                    ← 申请结果就地显示
```

- 状态：`已允许 / 待授权 / 已拒绝 / 不适用 / 未知`。能申请却没探到结果时显示「待授权」，
  比「未知」有用。
- 拿到授权后该行的说明文字会隐藏，页面自然变短。
- 被拒绝时显示「去这里打开：系统设置 → 应用 → 麻雀记 → 权限」和「再试一次」。
- 「全部申请」只问**待授权**的；被拒绝的不自动重问（系统通常不再弹窗）。

## 每个平台怎么申请

| 能力 | 浏览器 | 桌面 Tauri | Android / iOS |
|---|---|---|---|
| 位置 | `navigator.geolocation` | 不提供（插件是空实现，引导去「搜地点」） | `plugin-geolocation` 的 `requestPermissions` |
| 麦克风 / 相机 | `getUserMedia` | `getUserMedia`（WebView2 已放行） | `getUserMedia`（wry 转成系统权限） |
| 通知 | `Notification.requestPermission` | `plugin-notification` | `plugin-notification`（Android 13+ 要 `POST_NOTIFICATIONS`） |
| 文件读写 | 不需要 | 不需要 | 走系统「保存 / 打开」对话框，不需要存储权限 |

## 两个必须知道的限制

1. **Android 清单必须声明 CAMERA / RECORD_AUDIO**

   没声明时 `getUserMedia` 直接被系统回绝，连授权弹窗都不出现（logcat：
   `None of [...RECORD_AUDIO] in {...}`），页面只会显示「已拒绝」——看起来像坏了。
   `src-tauri/gen/android` 是生成目录，所以由 `scripts/android-permissions.mjs` 在构建前补齐，
   已挂到 `tauri.conf.json` 的 `beforeDevCommand` / `beforeBuildCommand`。详见 `04-打包指南.md`。

2. **安卓 WebView 查不到麦克风 / 相机的授权状态**

   `navigator.permissions.query({name:"microphone"})` 在 WebView 里直接抛错，所以重新进页面时
   麦克风 / 相机只能显示「待授权」——即使系统里早就允许了。
   这不是 bug 而是能力缺失，页面上的处理是写明：
   「点一次『申请权限』确认：已允许会直接通过，不会再弹窗。」（已授权时 `getUserMedia` 秒回，无弹窗）
   想彻底解决需要写一个用 `ContextCompat.checkSelfPermission` 的 Android 插件，目前没做。
