# 麻雀记（Sparrow Diary）· 贡献指南

跨平台、本地优先的日记/生活记录应用，使用 Flutter 开发。

## 环境搭建

### 前置要求

- Flutter 3.x（stable channel）+ Dart 3.x
- Git 与 GitHub 账号
- 平台构建工具：
  - Android：Android Studio + Android SDK（构建 APK 必需）
  - Windows 桌面：Visual Studio 2022（含「使用 C++ 的桌面开发」工作负载）+ Windows 10/11 SDK
  - iOS / macOS：Apple 环境（仅 macOS 主机）

### 克隆与安装依赖

```bash
git clone <repository-url>
cd note
flutter pub get
```

### 生成 l10n 与数据库代码

项目使用代码生成，改动模型或本地化后需要重新生成：

```bash
flutter gen-l10n          # 生成 lib/generated/l10n（本地化）
dart run build_runner build --delete-conflicting-outputs   # 生成 drift/riverpod 代码
```

## 代码结构

```
lib/
├── app.dart                 # 根组件：主题 + 路由
├── core/                    # 基础设施：主题、组件、工具
│   ├── theme/               # 主题规格与构建
│   ├── components/          # 通用组件
│   └── utils/               # json_helpers、media_hasher 等
├── data/                    # 数据层
│   ├── database/            # drift 表、DAO、迁移
│   ├── repositories/        # 仓库（标签、仪表盘配置等）
│   └── sync/                # 备份 / WebDAV / 加密
├── domain/
│   ├── enums/               # NoteType 等
│   └── note_data/           # 各笔记类型的 data class
├── features/                # 功能层
│   ├── dashboard/           # 仪表盘
│   ├── kanban/              # 看板
│   ├── notes/               # 笔记编辑/预览/日历
│   ├── notes_list/          # 时间线列表
│   ├── search/              # 搜索
│   └── settings/            # 设置
└── providers/               # Riverpod providers
```

详细的分层规范见 `docs/dev/02-笔记类型UI规范.md` 与 `docs/architecture/01-笔记类型架构.md`。

## 代码规范

- 遵循 `analysis_options.yaml`（`flutter analyze` 必须 0 error；现有 info 级提醒应尽量清理）
- 类型化 data class：不使用裸 `Map<String, dynamic>` 传递笔记数据
- 新增/修改笔记类型时对照 `docs/dev/02-笔记类型UI规范.md` 检查清单
- 使用 `import 'package:note/...'` 绝对导入；避免循环导入

## 测试要求

所有新增功能必须附带测试，位于 `test/`：

| 类型 | 目录 | 要求 |
|------|------|------|
| 单元测试 | `test/` | data class 的 `fromJson/toJson` 正常 + 边界 + 空数据 |
| widget 测试 | `test/` | 编辑器/卡片/预览渲染 |

```bash
flutter test          # 运行全部测试
flutter analyze       # 静态检查
```

## 提交规范

- 使用 [Conventional Commits](https://www.conventionalcommits.org/) 格式：
  - `feat:` / `fix:` / `refactor:` / `docs:` / `test:` / `chore:` / `build:`
  - 示例：`feat(notes): 新增 textV2 富文本导出`
- 提交前运行 `flutter analyze` 与 `flutter test`，确保无新增错误
- 不提交**任何**密钥文件：`android/app/upload-keystore.jks`、`android/key.properties`（已 gitignore）

## 打包与 CI

项目配置了 GitHub Actions 自动打包：

| Workflow | 触发 | 产物 |
|----------|------|------|
| `build-apk.yml` | 推送 `v*` 标签 / `main` / 手动 | arm64 + armeabi-v7a 两个 APK |
| `build-windows.yml` | 推送 `v*` 标签 / 手动 | Windows x64 ZIP |

### 本地打包命令

```bash
# Android APK（仅 ARM 架构）
flutter build apk --release --split-per-abi --target-platform android-arm64,android-arm

# Windows 桌面
flutter build windows --release    # 产物: build/windows/x64/runner/Release/
```

### 正式签名（CI）

推送到 `main` 前在仓库 Settings → Secrets 配置：

| Secret | 说明 |
|--------|------|
| `KEYSTORE_BASE64` | `upload-keystore.jks` 的 base64 |
| `KEYSTORE_STORE_PASSWORD` | 存储密码 |
| `KEYSTORE_KEY_PASSWORD` | 密钥密码 |
| `KEYSTORE_KEY_ALIAS` | 别名 |

未配置时 CI 自动用 debug 签名构建。

## 提交流程

1. 新建分支：`git checkout -b feat/xxx`（命名：`feat/`、`fix/`、`refactor/`）
2. 实现功能（附带测试）
3. 本地验证：`flutter analyze` + `flutter test`
4. 推送分支并创建 PR 到 `main`
5. PR 通过后合并（CI 会在 push `main` 或打 `v*` 标签时自动打包）
